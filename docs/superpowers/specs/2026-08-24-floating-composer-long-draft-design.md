# Floating Composer 长草稿模式设计

日期：2026-08-24
状态：已完成交互设计确认，等待规格复核

## 背景

当前 Floating Composer 已具备 `idle / focused / typing / expanded / sending` 动效，但尺寸仍与焦点状态耦合：输入框失焦后会回到窄小的 Idle 宽度。短草稿适合这一行为，长草稿则会因宽度骤减、换行增多而难以阅读。现有多行输入也缺少面向长文的排版工具和稳定的放大编辑形态。

本设计只重构聊天页底部 Composer。聊天消息区、导航、模型与供应商配置、附件、语音、草稿持久化和消息发送链路保持现有行为与兼容边界。

## 目标

- 短内容继续保持紧凑、居中、两侧留白的 Floating Composer。
- 长内容失焦或关闭键盘后仍保持足够宽度，不强制回到 Idle。
- 超长内容通过连续动画进入内容适配的 Large Editor。
- 在 Large Editor 内提供基础 Markdown 排版、撤销、重做、复制和清空工具。
- 保持 `ComposerOverlay`、`ModelSelector`、`MessageInput`、`SendButton` 四个 UI 边界；Model、Input、Send 仍是三个独立 Floating Surface。
- 保证宽高、留白、垂直位置、IME 避让、工具栏和 Send/Stop 的动画连续且克制。
- 保留焦点、选区、滚动位置、草稿恢复和发送失败恢复能力。

## 非目标

- 不实现富文本数据模型、Markdown 实时预览或独立写作页面。
- 不改变消息存储、对话运行时、模型调用、附件或语音协议。
- 不新增统一底栏背景，也不新增第五个 Floating Surface。
- 不在本次工作中重构聊天消息列表、导航或其他页面。
- 不持久化撤销/重做历史到应用重启之后。

## UI 边界

### ComposerOverlay

只负责 Composer 的整体几何和动画：水平宽度、左右留白、底部位置、Safe Area 与 IME 位移。它接收已经解析的尺寸模式和活动状态，不拥有草稿内容或编辑历史。

### ModelSelector

继续使用供应商官方无背景图标与箭头，保持独立 Surface。菜单从稳定锚点向上展开；打开期间不随 Composer 每一帧重新测量锚点，避免抖动。它与当前 MessageInput Surface 使用同一条垂直中心线。

### MessageInput

拥有同一个持续挂载的原生 TextInput，以及其视觉表面、选区、内容测量、长文工具栏和会话内编辑历史。Compact、Review、Large 是同一输入控件的不同几何形态，不通过卸载和替换切换，因此不得丢失光标、选区或滚动位置。

排版工具栏属于 MessageInput Surface 内部，不是独立 Floating Surface。

### SendButton

保持独立 Surface 和现有 `Disabled → Send → Sending / Stop` 语义。按钮与当前 MessageInput Surface 垂直居中；输入框增高只改变按钮的位置，不重建按钮。

## 双轴状态模型

Composer 使用互相独立的尺寸轴和活动轴。

### 尺寸轴

`Compact → Review → Large`

尺寸依据 TextInput 实际排版后的内容高度和行高解析，而不是仅按字符数判断。字符数只用于用户可见的统计信息。

#### Compact

- 空内容或短内容的默认停靠态。
- 稳定容纳约 1–2 个视觉行。
- Idle 时水平居中并保留明显左右留白。
- Focused 时可以先横向扩张；达到宽度上限后才继续纵向增长。

#### Review

- 中长草稿的阅读停靠态。
- 接近可用全宽，内容适配增长，最多展示约 5–7 个视觉行。
- 失焦、Android Back 收起键盘或点击消息区后继续保持宽度和高度。
- 内容超过可见高度时允许正文区域滚动。
- 提供内嵌的手动展开入口；该入口不成为新的 Floating Surface。

#### Large

- 超长草稿或用户手动展开后的编辑态。
- 从 Review 当前高度继续按内容自然增长，不为了达到某个比例制造空白。
- 高度上限取当前可用视口高度约 46%，同时受 Safe Area、IME 和最小消息区可见空间约束。
- 达到上限后只让正文区域内部滚动；标题/字符计数和工具栏保持可见。
- 失焦或关闭键盘后仍保持 Large。

### 尺寸阈值与滞回

- Compact 自动进入 Review：实际内容达到至少 4 个视觉行。
- Review 自动退出到 Compact：实际内容降到不超过 2 个视觉行。
- 3 行是滞回区，保持上一个尺寸，避免增删内容时抖动。
- Review 自动进入 Large：内容溢出 7 个视觉行，即达到至少 8 行。
- Large 自动退出到 Review：内容降到不超过 5 个视觉行。
- 6–7 行是 Large/Review 的滞回区，保持上一个尺寸。
- 用户可从 Review 手动进入 Large。
- 用户手动将 Large 收起后设置 Review 保持覆盖；即使内容继续增长，也不自动重新放大。覆盖持续到发送成功、正文变为短内容或用户再次手动展开。该覆盖只阻止自动重新进入 Large，不阻止短内容按正常阈值回到 Compact。
- 空草稿在发送成功、明确清空或正常编辑删除后回到 Compact。

阈值以规范化内容高度除以当前实际行高得出，必须兼容字体缩放。实现不得假设固定字符宽度。

### 活动轴

`Idle / Focused / Typing / Sending`

- Focus 和 Blur 只改变焦点描边、活动强调与键盘状态，不直接决定尺寸。
- Typing 表示存在可发送草稿并继续沿尺寸轴解析。
- Sending/Stop 保持现有发送语义，不引入新的消息状态。
- 发送失败恢复草稿后，尺寸解析器根据恢复内容自动回到原来的 Review 或 Large。
- 停止生成不得清空用户在生成期间新输入的草稿，也不得强制改变其尺寸。

## 几何与空间利用

- Model、Input、Send 是三个独立 Surface，外层行使用垂直居中对齐。
- Compact Idle 根据现有移动端布局预算居中，保留清晰左右空间；不强制固定 `1 : 1.5 : 1` 比例。
- Compact Focused、Review 和 Large 动态使用可用宽度，但仍保留 Safe Area 与合理边缘间距。
- Large 的 40–50% 是高度上限范围，不是固定高度。
- MessageInput 正文占据标题/统计与工具栏之外的全部空间。
- 工具栏固定为单行，视觉高度约 36–40dp；其下只保留约 6dp 内边距，不增加空附件区、占位区或空白尾部。
- 窄屏下，收起和“更多”固定在工具栏两端；中间排版工具可横向滑动并提供边缘渐隐提示。工具不得换成两行或压缩到不可触达尺寸。
- 所有图标操作具备至少 44dp 的有效触控区域，可通过容器和安全 hitSlop 实现，但相邻命中区域不得产生歧义。

## 长文工具

### 直接工具

- 撤销
- 重做
- 无序列表
- 有序列表
- 引用
- 代码块
- 手动收起
- 更多

字符数显示在 Large 的顶部信息区。Review 的展开入口只在多行草稿中显示。

### 更多模式

点击“更多”不打开新的弹窗或 Floating Surface，而是在同一工具栏中原位切换为：

- 复制全文
- 清空文本
- 返回排版工具

复制失败通过现有轻量提示机制反馈。清空必须经过现有对话框能力二次确认；确认后只清空受控文本，已有附件不受影响，并重置尺寸覆盖和编辑历史。清空确认后不可通过本工具栏撤销。

### Markdown 变换

- 无序列表、有序列表、引用对所有选中行执行可逆前缀切换。
- 如果所有目标行已经拥有对应前缀，则移除前缀；否则统一添加或规范化前缀。
- 无选区时作用于光标所在行。
- 代码块使用围栏包裹选区；无选区时插入成对围栏，并把光标放在中间可继续输入的位置。
- 变换必须保留换行风格，正确处理 Unicode、emoji 和多行选择。
- 每次变换后校正并恢复选区，然后继续聚焦当前 TextInput；不得因为点击工具而关闭键盘。

### 撤销与重做

- MessageInput 会话内维护最多 50 个文本与选区快照。
- 连续普通输入在约 600ms 编辑窗口内合并为一组，避免每个字符成为一步。
- 每个 Markdown 工具动作和大段粘贴形成独立检查点。确认清空会重置历史，不形成可撤销检查点。
- 新编辑发生在撤销之后时清除重做分支。
- 历史不写入持久化草稿，也不跨应用重启恢复。

## 数据流

1. 受控草稿、TextInput `contentSize`、当前选区、上一尺寸模式和手动覆盖进入纯尺寸解析器。
2. 解析器校验测量值，使用双阈值和上一模式输出 `Compact | Review | Large`。
3. ComposerOverlay 根据尺寸模式、活动状态、视口、Safe Area 和 IME 计算整体宽度与位置。
4. MessageInput 根据同一尺寸模式计算内容适配高度、正文滚动能力、展开入口和工具栏可见性。
5. Markdown 工具通过纯文本变换函数生成新的文本与选区，并回写现有受控草稿。
6. 所有工具产生的草稿更新继续经过现有 `markDraftChanged` 与草稿持久化链路；不建立平行存储。

建议将尺寸解析、Markdown 变换和编辑历史分别放在可单测的纯 helper/hook 中。它们不是新的 UI 组件，也不跨越聊天模块边界。

## Motion 与 IME

- 宽度、高度和左右留白共享一个连续几何进度，常规动效约 220–240ms，使用克制的 `inOut(cubic)` 类曲线。
- Large 收缩到 Compact 时从一个连续进度经过 Review 几何值，不插入人工停顿，也不瞬间跳回。
- 焦点描边、工具栏和 Send/Stop 使用约 130–170ms 的淡入淡出与极小尺度变化。
- 工具栏进入只允许轻微的约 6dp 位移，不使用弹簧过冲或夸张 bounce。
- Composer 垂直位置优先采用系统 IME 报告的实时高度、时长与 easing 同帧跟随；系统未提供有效曲线时回退到统一几何动效。
- 键盘出现导致可用高度不足时，重新计算 Large 上限并压缩正文可视区，正文承担滚动；工具栏和发送操作保持可触达。
- 键盘关闭或 Blur 不改变 Review/Large 尺寸目标。
- Reduced Motion 保留最终几何、IME 避让和状态辨识，但将装饰性位移缩短为近即时淡变。

## 容错与恢复

- 对非空文本忽略 `0`、非有限值和负数等无效瞬时 `contentSize`，继续使用最后一次有效测量。超长文本的合法内容高度可以远大于视口；解析器只对布局目标做上限约束，不丢弃原始长文测量。
- 屏幕旋转、窗口尺寸、Safe Area 或字体缩放变化时重新计算高度上限，但不无条件重置当前模式。
- 宽度动画导致文本重新换行时，尺寸解析仍使用上一模式和滞回区，避免反馈循环。
- 工具变换输出的选区始终夹取到新文本的合法范围。
- 保留现有乐观发送和失败恢复机制，不更改消息提交顺序。失败恢复的文本重新进入同一尺寸解析器。
- ModelMenu 只在打开前确定稳定锚点；Composer 动画期间不持续更新锚点。
- 任一增强工具不可用时，普通文本输入、发送和草稿恢复仍必须可用。

## 可访问性

- 所有工具提供明确的 accessibility label、hint、selected/disabled 状态。
- 图标不以颜色作为唯一状态表达；Send、Stop、撤销不可用等状态同时使用形状和语义。
- 字体缩放参与真实内容高度测量，不能通过固定字符数绕过。
- 工具栏横向滑动时，固定操作和可滚动操作都保持可被屏幕阅读器顺序访问。
- 清空确认说明不可恢复；复制成功与失败使用不会抢夺焦点的提示。

## 测试策略

实现遵循测试驱动顺序：先增加能正确失败的聚焦测试，再实现最小行为，最后整理结构。

### 纯逻辑测试

- Compact/Review/Large 的进入、退出、滞回和手动覆盖。
- Blur、键盘关闭、发送成功、发送失败、停止与清空的尺寸结果。
- 异常测量、字体缩放和窗口变化。
- Markdown 多行前缀切换、代码围栏、Unicode、emoji、CRLF/LF 与选区映射。
- 50 步历史上限、输入合并、撤销后新编辑和重做失效。

### 组件与布局测试

- 三个 Surface 在所有尺寸下垂直居中。
- Compact Idle 保持居中留白；Focused 平滑扩张；Review/Large 失焦后保持。
- Large 内容适配增长且不强制半屏；达到上限后仅正文滚动。
- 工具栏下无空白尾部；窄屏单行工具轨正常滚动。
- SendButton 的 Disabled/Send/Sending/Stop 视觉和 accessibility 状态。
- ModelMenu 锚点稳定、点击外部与 Back/ESC 关闭。
- 点击消息区使空或短输入真正 Blur；长输入 Blur 后只撤销焦点态。

## 验收标准

1. 空或短草稿失焦后平滑回到 Compact。
2. 至少 4 行的草稿进入 Review，失焦和键盘关闭后仍保持接近全宽。
3. 至少 8 行或手动展开进入 Large；Large 高度按内容增长且不制造空白。
4. Large 达到约 46% 可用高度上限后只有正文滚动，工具栏下方无明显空白。
5. 内容减少时按 5 行和 2 行退出阈值平滑降级，不在临界点抖动。
6. ModelSelector、MessageInput、SendButton 在所有尺寸下垂直居中且保持独立 Surface。
7. Markdown 工具、撤销/重做、复制和确认清空在 Android 真机可用，且不丢焦点或草稿。
8. 点击外部能真正 Blur；Blur 不会强制压缩 Review/Large。
9. Composer 与 IME 同帧移动，不遮挡输入、工具栏或发送按钮。
10. 消息区、导航、附件、语音、草稿恢复和既有发送/停止行为无回归。
