# 模型列表的有效密钥组归属

日期：2026-11-17。[完整应用目标](../architecture/full-application-improvement-goal.md)继续进行中。

Web真实发送验证发现，同一模型由key2完成回复，但模型列表仍归在已停用的key1；使用别名的C模型则落入供应商合并目录。模型分组遍历了停用密钥组，也只按显示模型ID匹配上游目录。

分组现在跳过明确停用的密钥组，使用现有别名解析规则建立上游模型索引，将别名和上游模型归入同一有效目录。多个目录包含同一模型时，每个显示模型仍只展示一次；没有有效密钥组目录的供应商模型保留在供应商合并目录。点击别名继续传入别名身份。上游厂商分组保持原规则。

三项回归覆盖停用组与启用组共享模型、多个别名及重复目录项、只有停用组但供应商目录仍保留模型的情况。旧工作区和独立main候选均三项失败；修复后工作区两组57项、独立main候选两组49项通过，两者类型检查通过，候选三项架构检查通过。两份现有文件均含其他未完成内容，提交候选只将本项源码差异和三项回归叠加到main。

本次提交的验证范围为组件行为、候选代码、类型和架构检查。修复前的Web七次跨成员发送、错误确认切换及16条持久消息已通过，原13项存储值和六个数据库文件已恢复；这些结果不构成新分组逻辑的Web或真机界面验收。新逻辑的当前源码界面复测继续，英文单项数量、菜单打开异常、原生意外导航、性能与全页面矩阵仍未完成。
