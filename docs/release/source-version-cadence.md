# 源码版本更新节奏

自 2026-11-14 起，沿用用户授权：只使用 `main`，每项功能或优化完成验证后立即以简体中文 Conventional Commits 提交并推送。默认每累计 5 项已验证、已推送的功能或优化提交，进行一次源码版本更新，并发布对应的 GitHub Release。

计数从 [版本检查点](./source-version-cadence.json) 的 `countedThroughCommit` 之后开始，以 `main` 中的提交和成功推送记录核对。功能、修复、性能、重构与界面优化提交计入；纯文档、测试、构建维护、版本提交，以及重复接入同一项改动的提交不重复计入。一次更新覆盖当前已累计的全部合格改动，完成后从本次覆盖的最后一个功能提交重新累计。

更新时同步 `package.json`、`app.json` 的源码版本和 Android 版本码、三语 README、版本索引、三语公开说明及维护记录。修复和渐进体验优化沿用当前补丁版本递增方式；版本范围需要调整时按实际变更处理。原有未完成改动继续保留，只提交本次版本与相关文档的最小差异。

版本更新完成验证、提交并推送后，创建对应版本标签并实际发布 GitHub Release。标签固定到该版本的源码提交，正文直接使用已提交的三语公开说明；发布后核对远端标签、正文、发布状态与最新版本。只提高源码版本或更新文档不算完成发布。2026-11-15 已补发 `v1.1.9` 和 `v1.1.10`，详见 [发布记录](./source-releases-1.1.9-1.1.10-2026-11-15.md)。

版本更新与 Release 发布均不执行构建、导出、安装或工作流派发，也不上传 APK。发布前检查当前工作流的触发事件，发布后核对是否产生新任务。`updates/android.json` 继续记录实际 APK 候选身份；源码版本递增不产生可安装资产。APK 与网站工作流沿用手动触发方式。

公开更新说明遵守本目录 [写法约定](./README.md)：只记录实际变化，按有内容的功能、改进和错误修复分类；测试数量、提交、构建过程、交付状态与验收限制放在独立维护记录。历史标签、发布说明、发布日期和附件保持原有记录。
