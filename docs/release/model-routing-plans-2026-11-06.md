# 模型路由方案首版 · 2026-11-06

入口：设置 → 供应商 → 管理路由方案；设置导航的管理区也提供入口。保存后，可在聊天的快捷模型菜单或完整模型配置面板中选用。

后续验收补充：同日的[功能与主题协调升级](./islemind-upgrade-2026-11-06.md)完成了全项目依赖与边界修正，最新结果为 997 文件/0 模块边界问题、14/14 架构项通过，并补充五主题、双模式、三宽度的 30 个路由任务用例。以下保留首版实施时的证据与状态。

## 已实现的行为

- 保存、编辑、删除命名方案。支持固定连接/模型，或首选连接/模型加一个备用目标；最多保存 50 个方案。
- 使用准确的连接 ID 与请求模型 ID，保留模型别名。查找目标支持搜索、每页 25 项和不可选原因；编辑时显示执行顺序预览。
- 跨供应商切换默认每次询问；用户可明确允许该方案的备用连接。同一连接下的备用模型不触发跨供应商询问。
- 会话保存选用时的方案副本。之后修改或删除模板不改变已有会话；重新选用模板才采用更新。选用普通模型清除该会话的方案。分支、SQLite 恢复和便携导入导出保留副本。
- 每个独立请求从首选开始；可切换时最多使用一次明确配置的备用目标。备用缺失、被禁用或不满足请求要求时终止，不扩展到其他连接或同连接的任意模型。
- 请求详情和尝试记录显示保存的方案名称、原始目标与实际执行目标。方案归属为本地诊断字段，不进入供应商请求载荷。工具续调保留方案归属，同时继续固定在实际产生上下文的来源。
- 保存失败保留草稿和重试入口，离开未保存编辑时提示丢弃；支持中文、英文、日文。

## 执行与模块约束

`src/core/modelRoutingPlan.ts` 定义无副作用、有版本和长度限制的引用结构，不包含凭据。Settings 管模板，Conversations 管会话副本，Providers 的公开 `routingPlanPolicy` 与既有解析器负责实际候选与策略。

现有能力、访问、凭据、健康、冷却、协议、取消、流式输出和续调检查继续生效；请求级策略可以收紧方案授权，不能把“每次询问”扩大为自动允许。已经输出内容或存在来源绑定时不切换。失败分类仍使用现有策略，例如身份验证失败不会仅因配置了备用就自动尝试另一个凭据。

指定备用意味着用户选择该目标，不表示其价格更低；本版没有价格/速度排序、多级备用、任务分类或网关服务。供应商地址、密钥和模型目录仍由现有供应商管理维护。
