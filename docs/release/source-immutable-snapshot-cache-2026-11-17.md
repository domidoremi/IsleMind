# 已验证不可变快照的重复捕获优化

`snapshotPlainData` 每次接收已冻结的供应商目录时，仍会遍历全部嵌套属性来确认其不可变性。当前原生目录序列化后为 578,052 字符；发送准备和执行资格复核会多次捕获这些数据。

现在用模块内 `WeakSet` 记录已完成完整验证的不可变对象图。只有所有可达节点都通过纯数据、无访问器和冻结检查后才记录，后续捕获可跳过已验证节点。弱引用不延长目录或凭据对象的生命期；浅冻结、可变子节点、循环引用和非法字段继续执行原有检查。

## 验证

- 独立 main 候选复现旧代码一项失败：十次重复捕获枚举属性 7,690 次；修复后三组 32 项测试、类型及三项架构检查通过。工作区对应三组 34 项与类型检查通过。
- 新增回归覆盖重复捕获工作量、冻结循环仍可到达可变子节点、验证失败后不得提前信任循环节点。
- 同一已安装原生进程、相同目录，实际初始化导出连续 20 次重复捕获总耗时约 627.76 → 22.50 毫秒。修复后首次重用仍完成约 21.73 毫秒完整校验，其余各次低于 0.1 毫秒。这是 debug 环境局部观察，不是整体聊天基准。
- 保护性重载一次后，实际加载 bundle 与当前 Metro 字节一致，完整快照模块、已初始化导出和源码映射匹配；2,126 项 stage 源码核对通过。
- 修复后真实界面发送 B/key2 请求，完整回复、17/13/30 tokens 与两条持久化消息一致。消息耗时 8.325 秒，发送前 6.810 秒，仍有明显准备延迟。修复前一次同类诊断为 8.674 秒、发送前 7.266 秒；重载及首次执行初始化不同，不作因果或稳定性能提升结论。
- 最终独立审计确认 53 表 3,256 行、四项 raw、六组草稿/恢复槽、实际编辑器、原路由/设备/日志和原外部前台完整。8 条过期原观测恢复、19 条测试派生记录清除；15 个观察包装、两项订阅和计时器移除，Inspector 自然关闭。
