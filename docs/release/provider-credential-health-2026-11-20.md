# 连接保存与密钥健康状态维护记录

本项修复连接详情保存时的健康状态误冲突。请求执行更新最近使用、最近失败及失败次数后，用户仍可保存连接配置；保存等待安全存储期间产生的新健康状态按密钥组 ID 保留。相同密钥保留健康记录，更换密钥清空对应记录。名称、地址、密钥启停、顺序、模型选择等真实配置冲突继续拒绝保存并保留草稿。

主线候选通过 5 组 69 项测试，工作区组合通过 5 组 95 项测试；两者类型检查与架构边界检查通过。测试覆盖安全存储等待期间的更新、密钥替换、重排、新增和删除，以及默认调用者的精确冲突检查。

当前源码 Web 复测通过界面修改、合成健康状态完成及真实键盘保存，确认最新健康记录保留；随后注入真实配置变化，保存被拒绝且草稿保留。加载组件已与同源完整脚本、模块范围和当前源码映射核对。本次健康更新使用公开 store 合成，没有发送模型回复请求。

证据位于 `test-evidence/implementation/provider-current-20261120-01/`：`health-applied-39.json`、`health-main-complete-jest-32.json`、`health-workspace-jest-32.json`、`web-health-source-42.json`、`web-health-modules-43.json` 和 `browser-health-fixed-44.json`。早期失败证据保留；两次 Web 截图均超时，未取得视觉通过资格。

原有 435 个未完成路径按内容哈希保护。原生基线回读包含 53 表、四份原始状态、六组草稿与恢复槽、编辑器和 70 条请求，均与基线一致。原生仍运行既有冻结源码，本项尚未同步及真机验证。
