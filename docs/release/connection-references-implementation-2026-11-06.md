# 连接引用与删除影响 · I 批实施验收

日期：2026-11-06。供应商连接详情新增按需展开的「连接引用」，显示使用该连接的会话、路由、场景和模型偏好，以及当前模型、首选、备用等角色。删除前可以检查数量和覆盖范围，再进入对应配置修改。

本批接续[功能与主题协调升级](./islemind-upgrade-2026-11-06.md)与[场景方案](./scene-plans-implementation-2026-11-06.md)。实现、行为回归、最终 Web 和工程门禁已完成；最终 Android、图册和交付绑定尚未完成。用户要求按当前状态发布源码版本后，停止继续验收，状态冻结于下列记录；本批不标记为完整验收通过。设计依据见[本批设计](../design/connection-references-2026-11-06.md)，封版范围见[1.1.8 源码发布记录](./source-release-1.1.8-2026-11-06.md)。

## 功能与边界

| 使用场景 | 行为 |
| --- | --- |
| 查看引用 | 连接页展开报告后才读取；显示读取时点，支持刷新。计数按对象，同一对象的当前模型、首选和备用角色分别列出。 |
| 配置归属 | 路由模板、场景中的配置副本、会话配置分别统计；最后应用来源和历史请求不属于当前依赖。模型使用请求 ID，名称与别名仅供显示。 |
| 历史与草稿 | 本地已加载配置覆盖相同保存 ID；未发送草稿单列。检查最多 2,000 条其他保存配置，剩余、损坏和孤立状态明确显示；每类最多提供 25 个定位项目，计数不受显示上限影响。 |
| 准确定位 | 打开准确的路由/场景编辑页；已删除目标显示不存在。已有编辑受原离开保护约束。较早会话按 ID 加载一条，保留历史分页；读取失败支持重试，不误报不存在。 |
| 删除影响 | 全部、无效和选中连接的确认均补充引用数量与检查范围。读取失败不打开删除确认，可重试；已有连接快照、生命周期、串行删除及持久化屏障继续有效。 |
| 删除结果 | 原事务调整默认连接并移除所属收藏；路由/场景/会话副本、最近模型偏好和历史内容保留原身份。用户明确选择替代目标后才改变配置。 |

报告只读取本机配置。SQLite 投影标题、模型和路由元数据；不加载消息、提示词、技能变量、凭据或执行记录。报告递归冻结，读取期间取消或本地配置变化会拒绝返回混合结果。报告表示读取时点的事实，不是对所有相关对象的事务锁。

## 架构和实际修复

Core 定义纯引用事实；Settings 投影模板与偏好；Conversations 投影会话并拥有元数据读取及记录持久化；Providers 负责分组与显示预算。Bootstrap 通过公开模块入口组合，Presentation 只接收窄读取端口并负责展示和导航。约束见[公开 API](../architecture/module-public-api.md)。

原生隔离验收发现分页历史覆盖缺陷：仅加载 40/81 条时，新建普通/引导会话及单条删除曾通过全表替换保存当前列表，导致未加载历史丢失。现在创建只保存新记录；单条删除通过 `ConversationRecordRemoval` / `deleteRecord` 在同一 SQLite 事务删除该 ID 的消息、状态及记录，并沿用原写入队列。清空全部、导入等显式全量操作保持原作用范围。未发送草稿不写库；删除使旧读取失效。失败保留数据库原内容并提供原错误反馈，可重新加载后重试。复现与修复验收均只使用独立样例数据库。

第二项修复是较早会话定位。原会话页只查内存，会把分页以外的准确 ID 显示为不存在。现在 `ensureLoaded(id, signal)` 等待先前记录写入后加载目标，保留分页游标、草稿和更新的本地版本；离开页面或删除目标后不发布过期结果。只有聚焦页面可以选中会话。Web/Android 验收新增实际点击第 41 条会话引用并核对原消息。

人工查看截图还发现，连接配置异常提示遮住了首条历史消息。消息区现在根据该提示的实际高度保留空间；字体、宽度与主题改变后重新测量，提示消失后恢复原间距。修复落在会话布局与状态层；Web 和 Android 验收显式核对历史消息在提示下方可见。

Android 的 Liquid Glass 提示层另有零高度父容器，导致可见操作的原生可访问区域为零。修复使用完整视口及 `box-none`，为提示提供有效可访问区域，背景消息仍可交互；不以截图可见代替节点边界检查。

## 页面与主题

沿用首页底部栏的轻边界、紧凑操作和清晰当前状态。连接引用使用现有 disclosure、轻列表、共享按钮与语义文字颜色，不新增独立材质系统。Minimal、Monet、Material、Liquid Glass、Animal Island 保留各自字体与材质；浅深模式及 320/390/960 CSS 像素分别验证。主题切换保留路由编辑的节点、文本、焦点和选择。原六份首页/底部栏参照保持不变，最终交付检查逐份核对哈希。

## 历史证据与资格范围

I1 Web 的两项 Animal Island 选择失败来自验收定位：脚本应操作外层 Select 触发器；修正后单独补验通过，原失败保留。I1 原生把持久化引导会话误作未发送草稿，发现上述分页覆盖缺陷；该失败记录保留。I2 用修复后的历史写入实现通过 260 个 Web 视图/140 检查与 63 个 Android 视图/7 组检查；它尚未包含较早会话的按 ID 定位，因此不作为最终完成证据。I3 已加入准确历史定位，但截图人工复核发现连接提示遮挡，I4 修复布局并增加检查后，又在 Android 发现 Liquid Glass 提示操作的可访问区域为零。I5 修正提示层容器并通过上述 Web、行为和工程检查，最终 Android 仍待完成。所有失败、较早截图和中止记录保留，不用旧图册替代最终验证。

设备为 Android 12 / SDK31，包名 `com.islemind.stage9`，优化 Hermes、开发支持关闭、无 INTERNET 权限、禁止备份。合成连接与会话不调用真实供应商；正式安装 `com.islemind.app` 的公开身份/APK 和 OS 显示、字号、夜间模式及辅助功能设置只读比对。未检查正式私有数据。

本批不认证 iOS、完整输入法/TalkBack/VoiceOver、多设备材质或真实供应商执行。报告的元数据覆盖和导航预算明确显示，不将未检查范围推断为无引用。验收阶段未修改正式 Android 安装；后续提交和源码发布单独记录，不补写原生验收结论。
