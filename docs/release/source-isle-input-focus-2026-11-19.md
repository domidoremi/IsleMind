# 输入框卸载时释放焦点

在 Android 的同模型路由编辑器中，输入模型搜索并选择结果后，搜索框已经卸载和注销，React Native 的焦点表仍指向旧输入。公开的 Keyboard.dismiss() 能清除该引用；1382 对此作了相反预期，报告保留 incomplete。1384 的后续输入检查又被只接受完整名称的断言中断，所有测试资料已移除，1385 独立复核原状态通过。

共享 IsleInput 现在在自身 layout cleanup 中检查本输入是否仍聚焦，并在子宿主引用脱离前调用本输入的公开 blur()。删除未聚焦输入时保持其他输入的焦点，受控值更新保留当前宿主与焦点。

[回归验证](../../test-evidence/implementation/native-routing-groups-20261115-01/isle-input-focus-validation-20261119-1386.json)在旧 main 和工作区均为六项失败、一项通过。修复后独立 main 四组 99 项、工作区四组 114 项及各自类型、架构检查通过，计数不相加。新增七项生命周期回归覆盖五主题卸载顺序、其他输入焦点和受控值更新；这些是代码级覆盖。

[Android 实测](../../test-evidence/implementation/native-routing-groups-20261115-01/native-routing-search-unmount-focus-20261119-1392.json)限定岛屿深色中文竖屏。实际输入名称及搜索、选择测试模型后，旧搜索框已注销，焦点自动为空，未调用诊断清理；随后公开 dismiss 保持为空。再次实际点按名称框、按末尾键并输入 -edit，得到完整草稿名称 Native group 1392-edit。未保存方案或发送模型请求。

第 36 份快照核对 2,144 项输入，设备缓存与服务端完整相同，源码映射、模块工厂、三字体、三语和挂载导出均已核对。源码准备导致的编辑器和路由重挂载、一次受保护重载单独记录，原进程保持。[最终独立复核](../../test-evidence/implementation/native-routing-groups-20261115-01/native-input-focus-restored-20261119-1393.json)确认原 53 张表、四 raw、六组草稿与恢复槽、全部资料、编辑器正文/附件/选区/焦点、当前路由、设备、实际前台及原 70 条请求一致。三条测试连接、七组安全凭据和临时引用已移除，Inspector 关闭，cleanup/pending 为空。
