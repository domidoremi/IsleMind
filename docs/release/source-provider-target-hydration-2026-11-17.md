# 执行重验的供应商凭据读取优化

发送前的三次执行重验原先逐一读取整个供应商目录的主密钥与密钥组，随后只使用已选供应商。现在重验传入已准入的供应商 ID，仅重新读取该供应商的凭据。初次选择、候选发现和故障切换继续读取完整候选目录。

完整的原始元数据目录继续传给凭据读取层，并保留派发前对全部已准入供应商的配置检查。选中密钥的实时读取、串行队列、读取前后取消检查、模型访问、健康、范围版本及执行身份检查沿用现有流程。没有添加凭据缓存。

## 验证

- 新增 8 项回归：显式与当前目录的重复重验、备用供应商身份、读取期间和派发前其他供应商的配置变更、取消、密钥移除及范围版本变化。旧代码新增 8 项失败，原有 7 项通过；修改后该组 15 项通过。
- 当前工作区 8 组 109 项测试与类型检查通过。独立 main 候选 87 项通过，另有一项执行期间更换访问设置的既有失败；未修改 HEAD 独立复现相同失败。该既有问题在当前工作区通过，修复未混入本项提交。独立候选类型及三项架构检查通过。
- 真机保护性重载一次；完整已加载脚本与当前 Metro 字节一致，两个解析模块的完整 factory、初始化导出及源码映射匹配，2,126 项 stage 输入核对通过。
- 真机真实输入与发送通过，选中三成员顺序优先路由组并执行 B/key2。完整回复、17/13/30 tokens 和两条持久化消息一致。15 个观察包装、两项订阅和计时器全部移除，未记录凭据内容。
- Web 当前实际执行脚本及四个相关模块源码匹配。11 项运行检查通过：每次重验只读所选供应商的主密钥及两个密钥组、其他供应商配置撤销、取消后停止读取、目标缺失时零凭据读取、原方法和 store 恢复、持久存储未变。Web 检查使用停用的内存测试连接，没有派发模型请求或写入测试凭据。
