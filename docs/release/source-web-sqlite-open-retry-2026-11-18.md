# 网页启动时短暂的 SQLite 文件占用

网页打开本地数据库时，上一页的工作线程可能还持有文件句柄。现在遇到浏览器明确报告的同步文件句柄冲突后，应用分别等待 100 和 250 毫秒，再次尝试打开数据库。数据库打开成功后照常加载数据。持续占用时仍显示启动错误，并保留手动重试入口。聊天、设置和供应商压缩状态的连接都使用这一规则。

独立测试地址使用浏览器实际的 SQLite 存储和独占文件句柄。旧版即使在第一次冲突后立即释放句柄，也要手动重试。修复后的页面在同样的条件下自动进入聊天。持续持有句柄时，三次打开均报告冲突。释放句柄并点击页面的“重试”后进入聊天。测试地址的设置、空供应商列表、空会话列表和当前会话标识与测试前一致。

工作区和独立 `main` 候选各四套 23 项测试通过，类型、架构契约和模块边界检查通过。测试地址创建的六个文件和两个本地存储键已清理。原测试会话的 13 项存储、六个文件、页面会话标识和 70 条请求记录均通过核对。多标签页长期同时编辑及其他类型的存储故障仍有各自的验收范围。
