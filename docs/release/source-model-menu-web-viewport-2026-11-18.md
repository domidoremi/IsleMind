# 调整浏览器视口后模型菜单的位置

网页聊天的模型菜单在打开时读取弹层与模型按钮的位置，并按可见区域限制宽高。菜单打开期间，窗口、可见视口或按钮的尺寸变化会更新位置。浏览器延迟发送尺寸事件时，菜单每 250 毫秒检查一次可见视口，尺寸或偏移变化后才重测元素，关闭菜单时移除监听和定时器。

同一页面连续缩到 900×420 时，旧实现的关闭按钮上缘两次落在视口上方约 62 和 44 像素。保持菜单打开并缩到 320 像素宽时，按钮还曾移出右边缘。修复后，连续缩放前后打开菜单和保持打开时改变窗口尺寸的九个场景均通过，菜单完整可见，关闭按钮四边可命中。在 900×600 页面上，打开前与打开后放大到两倍的两组检查也通过，可见区域均为 450×300 CSS 像素。这些场景中浏览器未发送尺寸事件。

工作区与独立 `main` 候选各四套 42 项测试通过，工作区类型检查通过。新增回归覆盖打开时获取当前尺寸、视口遮挡、移位、事件延迟和关闭后的监听清理。浏览器实际加载的菜单、输入区容器、菜单定位与 Web 尺寸模块均与当前源码及对应脚本的可执行内容一致。复验后原有 13 项存储、六文件共 815104 字节、当前页面会话及 70 条请求记录保持一致。

本项覆盖浏览器动态尺寸与两倍缩放。手机实体输入法、真实按键以及其余页面的无障碍、视觉和性能验收继续跟进。
