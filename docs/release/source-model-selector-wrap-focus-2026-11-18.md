# 聊天输入区折行时的模型按钮焦点

Web 聊天页宽 640 像素时，输入框获得或失去焦点会改变输入区布局。原界面把模型按钮移到了另一个父节点，按 Shift+Tab 离开输入框后焦点落到页面主体。现在模型按钮保留在原父节点，输入框和控制行通过 flex 排序与折行定位。原生继续使用既有布局。

新增回归在旧实现上复现了按钮节点被替换。修复后，工作区三套 59 项测试通过。从 `main` 单独提取的提交内容通过三套 47 项测试。此前鼠标焦点用例里四个仅在工作区存在的模块模拟已移除，独立检出也可运行该用例。

浏览器中已将挂载的输入组件与当前源码及其可执行内容比对。在 640 像素宽度把焦点从输入框移到模型按钮，两者均保留原节点，折行后的控件互不遮挡。中英日三种语言在 320×640、640×800、900×420、1280×900 下，通过 DOM 打开菜单后，焦点进入对话框。点按关闭元素或派发 Escape，24 个组合的焦点均回到原按钮。每种尺寸完成后，原始存储、当前页面会话和请求记录通过核对。

此次浏览器能接收可信文本输入，普通按键未到达页面。真实 Tab、Shift+Tab、Enter、Space、Escape 仍待复验。本项仅覆盖 Web 折行时的节点和焦点。动态缩短视口时菜单上缘越界另行跟进。
