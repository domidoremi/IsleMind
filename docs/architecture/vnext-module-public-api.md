# vNext Module Public API Manifest

This manifest is the allowed cross-module import surface for the in-progress vNext tree. Consumers import only the listed `index.ts` entry point; internal folders such as `domain/`, `application/`, `ports/`, `adapters/`, and `testing/` are private to their owner.

The target product/runtime is Chat-only. This manifest lists current public APIs only. Older writers and removed persisted formats are unsupported: no product-mode conversation metadata, Agent AssistantRun decoder, conversation cache, Tavern v1 envelope, key-value-to-SQLite migration, legacy storage facade, or portable recovery-blob fallback may appear on the public surface.

**Current Chat workflow cutover:** `@/modules/assistant-runtime` publicly exports `createAssistantChatWorkflowRunRuntime`, and `@/bootstrap/vnextChatWorkflowRuntime` composes it with Knowledge context assembly and the current workflow checkpoint store. Every explicit workflow executes as `kind: 'chat'` and carries its exact Chat `AssistantRunId` through resolution, checkpoints, tasks, confirmations, artifacts, cancellation, and recovery. `AssistantRuntime.recoverInterruptedRuns()` accepts no run-kind filter. Persistence reads and writes only Chat rows; non-Chat rows fail closed. SQLite migration v5 remains only as an inert migration-ledger tombstone and no late Agent decoder is public or private.

**Current Chat workflow presentation:** `@/modules/conversations` publicly exports `createConversationChatWorkflowReplyStarter`; `@/bootstrap/conversationReplyStart` installs the same starter for explicit workflow dispatch and confirmed-action restart. Tasks activity admission accepts only `chat-turn | chat-workflow` with exact conversation/message/run identity. Catalog discovery and restart are mode-free, and no prior-message mode or product metadata enters the seam. The Chat task card may cancel the exact bound live AssistantRun; unbound activity cancellation remains observational only.

**Current mode-free Chat execution contracts:** Chat-only public entry contracts govern workflow entry, assistant-message resolution, cancellation, confirmation, retry/regenerate, pending model-operation projection, and `/chat/:id` opening. Conversation, message, task, catalog, provider-tool, tagged-MCP, planning, prompt, durable-dispatch, and workspace contracts expose no `productMode` or mode generic. Current records contain no Agent/Companion metadata and no compatibility decoder reconstructs it. Architecture and behavior gates reject mode-bearing ordinary reply inputs, extra call-site arguments, mode-specific prompt branches, and old mode projection helpers.

**Current Chat workflow resolution contract:** `@/modules/tasks` publicly exposes the Chat-owned workflow runtime policy, while `@/bootstrap/conversationChatWorkflowResolutionRuntime` binds its Conversations projection, workflow, catalog, Knowledge, search, clock, and trace dependencies. The trace dependency names are `projectTrace` and `clampWorkflowOutput`; the internal skipped-result helper and ephemeral non-handled reason are `skippedWorkflowRuntimeResolution` and `workflow-not-handled`. The former Agent-named dependency/helper names and `agent-not-handled` reason are deleted and restoration-gated. These are in-memory application contracts only and do not alter task, checkpoint, trace, or conversation persistence.

## Generation Parameter Contracts

- `@/core` exclusively exports the provider-neutral `ReasoningEffort`, `GenerationParameterKey`, `GenerationParameterSource`, `GenerationParameterSources`, and `resolveGenerationParameterSources()` contracts. `ChatRequest` requires parameter provenance without naming provider wire fields. The former `providerContracts` and broad `types` barrel re-exports are deleted and architecture-gated against restoration; Providers may import the Core type internally for provider metadata but cannot re-export it.
- `@/modules/conversations` publicly exports `ConversationSnapshot` v2 and its strict parser. Version 2 persists `reasoningEffort` plus `generationParameterOverrides`; v1 and unversioned records remain readable, while unknown versions and invalid reasoning/override values fail closed. A missing legacy override map preserves finite stored values as `explicit`; a present empty map means provider defaults.
- `@/modules/providers` owns `ProviderRuntimeChatRequest`, the endpoint-aware per-field support result, `ProviderRequestParameterPlan`, and final conformance diagnostics. Runtime and planning requests require an explicit `GenerationParameterSources` map; untyped input without one is treated as provider-default and omitted instead of inferring explicit authority from a numeric value. Each generation parameter records `included | omitted`, source, reason, wire path, and optional value before serialization. Body builders consume only included values; conformance then merges the plan with the actual body as `omitted-as-planned`, `retained`, `removed-after-serialization`, `adjusted-after-serialization`, or `unexpectedly-included`.
- `@/bootstrap/providerRequestBinding` and `@/bootstrap/providerParameterMatrix` bind model metadata, provider declarations, reasoning constraints, and serializer capabilities. OpenAI Responses does not advertise or emit `top_k`; its Top-K field is `unsupported-endpoint`. Sampling and Token Budget aggregate states are derived only from their per-field results, so max-token support cannot imply sampling support.

## Model Operation Protocol

`integrations` owns the immutable `ModelOperationCatalogSnapshot`, canonical descriptors, `ModelOperationProposal`, normalized calls, bounded receipts, strict whole-output `islemind.model-tool-call.v1` parsing, and mode-free catalog admission. `assistant-runtime` owns the bounded one-operation turn loop, `PendingModelOperation`, `awaiting-confirmation` run state, receipt continuation, cancellation, and recovery. `tasks` owns trusted bootstrap-issued authorization attestations, durable task policy, confirmation, and idempotency. `bootstrap` freezes one catalog revision per run, maps provider-native calls and structured fallback into the same contract, binds concrete executors through `taskBoundToolRuntime`, and reconstructs a catalog-bound session for confirmation. Catalog discovery receives no mode; internal and external task dispatch, including pending and approved confirmation replay, use exact Chat policy context that is not added to persisted task identity. Agent-named catalog contracts remain compatibility vocabulary, while the Agent-named executor path and APIs are deleted and restoration-gated.

## Rules

1. A new cross-module use must be added to the owning entry point and this manifest before it is consumed.
2. `bootstrap/` may construct concrete adapters but must import module public entries only.
3. A compatibility facade must name its target owner and deletion condition in `vnext-migration-status.md`.
4. A public API is not permission to import a concrete adapter from another module.
